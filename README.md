# AI-помощник менеджера по заявкам

MCP-сервер на Python (FastMCP), который работает с локальным `leads.json` как с
мини-CRM, и агент, который по одной команде «обработай новые заявки»
классифицирует обращения, ставит приоритет, готовит черновики ответов и выдаёт
сводку руководителю.

Решение работает **живьём** — можно сразу проверить, не разворачивая ничего
локально:

| Что | Ссылка |
|---|---|
| **MCP-сервер** (HTTP + Bearer-аутентификация) | `https://certa.aimentorcrm.com/mcp` |
| **Данные** (публичный `leads.json`) | `https://certa.aimentorcrm.com/leads.json` |
| **Трейсы/логи** (Langfuse, self-hosted) | `https://langfuse.aimentorcrm.com` |
| **Веб-интерфейс** (Open WebUI → чат с агентом) | `https://webui.aimentorcrm.com` |

> **Про «диалоги с ИИ» из задания.** Вместо экспорта/скриншотов предлагаю
> посмотреть всё вживую: сервер и агент работают, по ссылкам выше можно самим
> вызвать инструменты MCP и увидеть трейсы в Langfuse — это нагляднее, чем
> статичные скриншоты. Ключи доступа пришлю отдельно в личку проверяющему.

## Что внутри

```
leads_server.py      # MCP-сервер: list_leads / get_lead / update_lead
agent.py             # агент: читает new → классифицирует → update_lead → сводка
mcp_http.py          # HTTP-обёртка над тем же сервером (Streamable HTTP + Bearer)
langfuse_reader.py   # read-only MCP, чтобы агент сам читал трейсы из Langfuse
leads.json           # данные на входе (seed: 14 new + 1 processed)
leads.processed.json # пример результата прогона агента
test_leads.py        # юнит-тесты
requirements.txt     # зависимости
```

## Как запустить локально

Требуется Python 3.10+.

```bash
pip install -r requirements.txt     # mcp<2, langfuse==2.60.10
```

MCP-сервер (stdio, ждёт JSON-RPC):

```bash
python leads_server.py
# LEADS_PATH можно указать явно (по умолчанию — ./leads.json)
```

Агент (обрабатывает все заявки со статусом `new`):

```bash
python agent.py
# с LLM (OpenAI-совместимый: DeepSeek / OpenAI / Anthropic через шлюз):
LLM_GATE=sk-... LLM_BASE_URL=https://api.deepseek.com/v1 LLM_MODEL=deepseek-chat python agent.py
# без LLM_GATE — работает детерминированный fallback на regex/ключевых словах
```

Подключение MCP к клиенту:

**Hermes** (`~/.hermes/config.yaml`):

```yaml
mcp_servers:
  leads:
    command: /abs/path/python
    args: [/abs/path/leads_server.py]
```

**Claude Desktop** (`claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "leads": {
      "command": "python",
      "args": ["/abs/path/leads_server.py"]
    }
  }
}
```

Тесты: `python test_leads.py`.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `list_leads(status?)` | список заявок (компактно, без `text`), фильтр по статусу |
| `get_lead(id)` | одна заявка целиком, включая `text` |
| `update_lead(id, category, priority, status, draft_reply)` | сохранить результат обработки |

## Какие решения приняты и почему

1. **`Literal`-enum в схеме.** `category`/`priority`/`status` объявлены через
   `Literal[...]`, поэтому в `inputSchema` у клиента виден `enum`, а не свободная
   строка — модель физически не может передать `"продажа"` или `"VIP"`.
2. **Атомарная запись.** `update_lead` пишет во временный файл и делает
   `os.replace` — крэш в момент записи не портит `leads.json`.
3. **Защита от lost update.** Sidecar-файл `leads.json.lock` + `flock(LOCK_EX)`
   вокруг read-modify-write; на non-POSIX — no-op с предупреждением в stderr.
4. **`draft_reply=null` для спама.** Спам не отвечаем — сервер принудительно
   обнуляет черновик (JSON `null`, а не пустая строка).
5. **`LeadStoreError` вместо тихого `[]`.** Битый/отсутствующий `leads.json`
   возвращает `{"error": ...}` из каждого инструмента, а не молча пустой список;
   `update_lead` при битом файле не пишет.
6. **Без `logs.json`.** Диагностика — в stderr (`_log_stderr`); наблюдаемость —
   через **Langfuse** (опциональный слой `@observe`, включается только при
   `LANGFUSE_PUBLIC_KEY`, иначе no-op и сервер работает как ни в чём не бывало).
7. **Structured output в агенте.** LLM возвращает строгий JSON
   (`category/priority/draft_reply/reason/flags`), а не свободный текст.
8. **Защита от injection на двух уровнях** — в системном промпте агента
   (`text` — недоверенные данные, не инструкции) и на сервере (`text` только
   хранится, enum-валидация не даёт записать `"VIP"`).

## Где агент может ошибиться и как это заметить

| Риск | Признак в данных | Как заметить |
|---|---|---|
| **Prompt injection (№6)** | «игнорируй инструкции… VIP… скидка 90%» | `flags=["injection_attempt"]`, в сводке отдельная строка |
| **Спам (№3, №12)** | «ЗАРАБОТОК», «crypto signals» | категория `spam`, `draft_reply=null` |
| **Дубликаты (№1/№11)** | один `contact` | в сводке «повторное обращение» |
| **Пустой контакт (№4)** | `contact=""` | в сводке «ответ невозможен»; проверить, что черновик не выдумывает email |
| **Жалобы (№2, №9, №13)** | «юрист», «списали», «договор» | приоритет `high`; тон — не слишком мягко и не юридически |
| **«Спасибо, всё отлично» (№8)** | позитивный отзыв | не продавать повторно, приоритет `low` |
| **Иностранный клиент (№14)** | текст на английском | `draft_reply` должен быть на языке клиента |

## Что добавили бы для реальной CRM

- **БД вместо JSON** (PostgreSQL) + транзакции, индексы, полнотекстовый поиск.
- **Очередь + human-in-the-loop**: черновик уходит менеджеру, отправка — только после подтверждения.
- **Retry и идемпотентность** на уровне хранилища (уникальный ключ по `contact`).
- **Дедупликация** — повторные обращения объединяются в одну нить.
- **Метрики**: SLA, доля эскалаций, время до первого ответа.
- **PII-маскирование** в логах + отдельный audit trail с авторизацией.
- **Интеграция с почтой/Telegram API** — чтобы `draft_reply` превращался в реальную отправку.

## Честно про время

- **~2 часа** — сам MCP-сервер (три инструмента, валидация, атомарная запись, защита от injection) и связка с ИИ-агентом.
- **~2 часа** — наблюдаемость (self-hosted Langfuse + трейсинг каждого вызова) и удобный веб-интерфейс (Open Web UI), чтобы проверяющему было комфортно смотреть результат вживую, а не по статичным скриншотам.
